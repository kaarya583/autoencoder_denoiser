## Architecture, compression and datasets

The selected model is a freshly trained **GTCRN-based causal denoiser with frame-local RMS normalization**, **23,669 learned parameters**, 16 kHz audio, FFT512 and hop256. Its 32 ms analysis window and 16 ms hop describe framing, not measured end-to-end device latency. Spectral magnitude/real/imaginary features feed an ERB-compressed grouped convolutional encoder/decoder with recurrent attention and grouped dual-path GRUs. Temporal processing is causal; bidirectional frequency recurrence operates within each frame.

The new packed model is **46,784 bytes**, including neural arrays, INT32 biases, tables, descriptors and DSP constants. Relative to the historical U-Net's **2,963,714 parameters / 11,854,856 raw FP32 parameter bytes**, this is **125.22× fewer learned parameters and 253.40× smaller defined model payload**. This combines architecture replacement and quantization; it is not a 253× gain from INT8 alone, nor a measured quality-preserving compression of the original checkpoint. The compact network's own raw FP32 learned parameter payload is 94,676 bytes; its complete packed representation is approximately 2.02× smaller.

Neural weights, materialized activations and histories are INT8, with INT32 biases/dot accumulations and bounded wider integer operations where required. FFT, spectral features, ERB processing, complex-mask application and overlap-add remain float DSP. No learned-weight pruning, INT4 deployment or demonstrated distillation benefit is claimed.

Training uses 10,802 VoiceBank paired utterances (26 speakers, approximately 8.76 hours), 25,675 LibriSpeech clips (226 speakers, approximately 90.53 hours), and 837 MUSAN noise recordings. Development uses two held-out VoiceBank speakers, and a separate external cohort drawn from 25 held-out speech speakers and 93 held-out noise recordings. The external evaluation covers five SNR conditions plus a clean preservation cohort.

GTCRN is an existing architecture. Supported contributions currently lie in the exact integer recurrent implementation, calibration/QAT, efficient constant representation, and validated C deployment path. The exact sparse ERB representation uses 2,040 bytes and 1,910 coefficient products/frame versus 61,440 dense products/frame. Architectural novelty has not been established.
